# 项目文件夹与不可变原件

**一句话**:**导入即留档** —— 原件按内容哈希不可变地存进项目,库里只放解析结果和一根指向原件的指针。项目里从此只有两种东西:**不可变文件**,和**活的连接器**。

## 0. 现状:原件一份都不在我们手上

不是"存得不够好",是**根本没存**:

| 入口 | 今天存了什么 | 原件 |
|---|---|---|
| 表格导入 | 前端 `XLSX.read` 解析 → `POST /api/table/import` 只送**行** | 从未保存 |
| 对话里传文档 | `ingestDocumentText(…, text, …)` 只存**抽取出的文本**+分块向量 | 从未保存 |
| Compass 装载 | 拉来的行 + 一个来源戳 | 远端有,本地是缓存 |

所以「原始数据」这个说法今天名不副实。用户桌面上那个 `三级计划.xlsx` 是**唯一一份**;我们手里只有它的一次解析结果,而且无从知道解析的是哪一版。

`Project` 也还没有文件夹这个概念(只有 `id / name / sources / managed / enabled`)。

## 1. 模型:项目里只有两种东西

| | 例 | 性质 | 界面上说什么 |
|---|---|---|---|
| **不可变文件** | 原件、导出的快照、agent 产出的报告 | 存下来就不变 | 「来自 三级计划.xlsx · 8月14日」 |
| **连接器** | Compass 排产 | 永远现拉 | 「上次刷新 3 分钟前」+ 刷新 |

**活的只有一种,其余全是死的。** 要把活的固化,走一个显式动作:**导出快照** → 生成一个不可变文件,跟原件放同一个货架。

这条线比"文件夹是权威 vs 库是权威"清楚,也接得上前一刀:**凡是缓存,都得能说出自己有多旧**。

## 2. 项目 = 一个本地文件夹

`Project` 增加 `folder: string`(用户选)。布局:

```
项目文件夹/
  三级计划.xlsx                       ← 你看得见的那一份(可读可改,改了不影响下面)
  二级计划.xlsx
  分析/瓶颈复盘 v2.md                 ← agent 产出
  快照/排产-2026-08-14 15-20.xlsx     ← 显式导出,从此不变
  .veylin/
    originals/a3f1c2b4d5e6/三级计划.xlsx   ← 不可变原件,按内容哈希存,只读
    originals/9b02e7f1a2c3/三级计划.xlsx   ← 改过再拖回来 = 另一个版本,两份都在
    manifest.json                          ← 这个文件夹里有哪些原件、什么时候进来的
```

**索引和解析结果留在应用数据目录,不进文件夹。** 文件夹里只放**原件、产物、manifest** —— 这样把文件夹拷到另一台机器,带走的是能自己解释自己的东西;索引丢了可以从原件重建,反过来不行。

## 3. 导入即留档

任何入口(拖进对话、拖进表格面板、把文件夹里的新文件确认吸收)都走同一条:

1. 读字节 → `sha256`
2. `originals/<hash前12>/` 不存在 → 写入原件,设只读位
3. 解析 → 行/文本进库,记 `source_file = { hash, name, importedAt, fromPath }`

由此自动得到:

- **同一文件导两次** = 同一 hash = 不重复存,只多一条"又见到一次"的记录
- **改过再拖回来** = 新 hash = **新版本**,两份都在,能对比
- **外面把副本改了** = 哈希对不上 = 它已经是**另一个东西**,我们不会误以为还是原来那份

**不做文件监听(`fs.watch`)。** 不需要:我们只认哈希,不依赖外部文件的现状。这比监听 mtime 简单,也比"把原件藏进 .db"诚实。

**为什么原件按原样存文件,不塞进嵌入式库**:取回自己的东西不该依赖我们的应用还能跑。库损坏、schema 变了、应用装不上——原件都得能在 Finder 里双击打开。库擅长的是解析结果、索引、指针,那些丢了可以重建。

## 4. 来源指针:两类,不混

`TableSheetMeta.source` 今天只表达 MCP 来源。扩成判别式两类:

```ts
type SheetSource =
  | { kind: 'connector'; server: string; project?: string; tenant?: string; loadedAt: string }
  | { kind: 'file'; hash: string; name: string; importedAt: string };
```

界面一眼能分:连接器给「上次刷新 X 前」+ 刷新;文件给「来自 xxx.xlsx · 8月14日」+ 重新解析。知识库文档同样记 `source_file`。

## 5. 导出与快照

- **导出**:任何 sheet → xlsx,写到用户选的位置(默认项目文件夹)。
- **快照**:连接器视图 → 生成不可变文件,文件名带生成时间,内容旁记来源与行数。**从此不变** —— 这是"我要当时那一份"的唯一正解,不是让缓存偷偷变成事实。

### 5.1 agent 产出:按"谁要的"分三档

Claude 那边 agent 产出**就是文件**,直接写进项目文件夹,UI 只是把文件夹列出来
(Show in Folder),版本就是文件名(v1 / v2 / v2.1)。**不照抄**:那边一次任务
产一两个交付物;我们的诊断报告、影子对比是**答问的副产品**,一天几十个。全落
文件会把项目文件夹变成日志目录 —— 堆两百个 `影子对比-1786690888614.md`,人
再也不去看。

| | 例 | 落不落 |
|---|---|---|
| **人明确要的** | 汇报页、交付风险报告、导出的表 | **默认落文件**,不问 |
| **答问的副产品** | 诊断、影子对比、试排结果 | **留在对话里**,可寻址,旁边一个「另存到项目」 |
| **成为过依据的** | 那份被拿去提交变更的影子对比 | **自动落文件**,不问 |

第三档是这一节的重点:一个中间产物**一旦被后续动作依赖**(人看着它按了"提交"),
它就不再是中间产物,而是**这个决定的依据**,将来要能翻账。于是"该不该留"从
"用户记不记得点保存"变成**由事实决定** —— 与治理提案、版本回滚、来源戳同一条线。

两条命名规矩:

- **按事件命名,不按时间戳**,并且分目录:`报告/交付风险 2026-08-14.md`、
  `证据/影子对比 提案#128.md`。不要 `影子对比-1786690888614.md`。
- **同一件事重跑就覆盖(或 v2),不堆积**。诊断重跑是同一件事的新结果,不是新增
  一个文件;否则一周后文件夹里躺着 40 个「交付风险」,哪个是最新的没人说得清。

## 6. 文件夹里冒出来的新文件:显式吸收

打开项目时扫一遍(只扫顶层 + 常见后缀),不在 manifest 里的 → 提示「发现 2 个新文件,导入吗」。

**不自动解析。** 顺手往文件夹里放一份 ≠ 它就是项目数据;自动吸收会让"这东西什么时候进来的、谁放的"变成无人知晓。

## 7. 不做

- **文件监听 / mtime 追踪** —— §3 已解释:只认哈希。
- **把原件塞进 .db** —— §3 已解释:取回不能依赖应用还能跑。
- **自动吸收文件夹里的新文件** —— §6。
- 全文检索、跨机同步、云备份、原件的差异比对(diff)。都是后面的事。

## 8. 测试计划(先写测试)

1. 同一文件导两次 → **一份原件**,两条导入记录。
2. 改一个字节再导 → 两份原件并存,sheet 的指针指向新的那份,旧的还在。
3. 原件写入后是只读的;**被外部改动后哈希对不上** → 明说"这不是当初那一份",不静默沿用。
4. 导出 → 改 → 拖回来 → 新版本,旧版本仍可取。
5. 快照文件逐行等于生成那一刻的 sheet 内容。
6. 往文件夹里放一个新文件 → 不自动进库,但被列为"待导入"。
7. 项目文件夹被移走/删掉 → 启动时校验 manifest,**溯源断了要明说**,而不是假装原件还在。

## 9. 风险 / 未决

- **磁盘翻倍**(原件 + 解析结果)。3MB 的 xlsx 无所谓;真出现 GB 级原件再说。
- **只读位在 Windows / 网络盘上行为不一**。哈希才是真保证,只读位只是防手滑 —— 不要把正确性押在它上面。
- **文件夹被删/移走**:原件没了,解析结果还在但溯源断了。必须明说(§8.7),这与"陈旧数据被当依据"是同一个病。
- (原未决已定,见 §5.1。)
