# 对话 → 致用录(Playbook)

**一句话**:用户和 agent 跑通(grounded)的一段对话,可以被结晶成一条**可复用的致用录(Playbook)**,下次一句话/一键直接跑。人机共创、越用越强。领域无关——排产只是第一个实例。

Status: DRAFT · 2026-07-07 · owner: gushirui

---

## 0. 命名

- **中文:致用录**(取自「学以致用」+「录」)。恰好命中内核:*你和 agent 把事做通了(学)→ 结晶下来下次直接用(致用)→ 存成一册(录)*。三字对齐既有侧栏「自动化」。
- **英文:Playbook**(对齐 2027 业内标准,见下)。

**为什么英文是 Playbook 不是 Skill**(2027 已分两层):
- **Skill** = **原子能力单元**。Anthropic 2025-12 的 **Agent Skills 开放标准**(agentskills.io;Codex / MS / Cursor / Copilot 采纳),SKILL.md = 一包指令+元数据+资源。**我们的 MCP 工具(get_resources 等)就是这一层的原子。**
- **Playbook** = 把多个 Skill/工具 + 知识组合成的**多步、可触发、可共享的工作流**(WRITER、Salesforce 用此词)。

> **映射**:Skills = 原子;**致用录 / Playbook = 在对话里跑通后结晶出的可复用多步规程 = 本 spec 核心对象**。用 "Skill" 称呼我们这东西会和标准原子含义撞车,故英文用 Playbook。

## 1. 为什么

Veylin 现在的工作流靠用户**从空白画布手画节点**。但真实姿势是:用户先和 agent 把一件事**聊着做成了**;那段"调了哪些工具、什么顺序、什么参数"的过程,本身就是一个可复用规程。

产品内核:**把"跑通过的对话"结晶成"一条致用录"**。复用的单位不是代码、不是手画 DAG,而是"**你和 AI 一起做过、而且做成了的一段事**"。grounded(真跑通)是它值得复用、且不 hallucinate 的前提。

飞轮:`用 → 对话 → grounded → 结晶成致用录 → 复用 → 再对话精炼`。工作台越用越有能力,且这份能力是用户自己的对话长出来的。

## 2. 产品原则(贯穿全篇)

- **对话是唯一创作面**:创建 / 触发 / 修改 都从对话走,不填表、不画布(前期)。
- **AI 提议、人拨边界、系统守界**:参数弹性由 AI 推理提议,人用对话纠正,系统验证并守界。**带护栏的共创**。
- **诚实**:AI 标注哪些是它推断的(inferred)可调/固定,给理由。沿用 real/inferred 那套。
- **不提前造 / 不制造选择**:只有当对话确实"多步 + 达成了某结果"才提示结晶;安全默认、危险处才要人。
- **不割裂**:致用录不新开平级 tab,归入既有侧栏(见 §6)。

## 3. 核心模型

一条 **致用录(Playbook)= 步骤序列 + 参数谱 + 触发方式**,三样全从对话设与改。

### 3.1 步骤序列
从对话的 tool-call 轨迹归纳出的有序步骤(含依赖/数据流)。轨迹已全在消息里(工具名/入参/结果/顺序),**零额外埋点**。

### 3.2 参数谱(关键:AI 推理,不是人标注)
对每个值,AI 依语义推断其"性质",是一条谱而非二元:

| 档位 | 含义 | 例 |
|---|---|---|
| **锁定 locked** | 结构性、动作本身,不作参数 | `reschedule` / `提交落库` |
| **可调 adjustable** | 一个你这次挑的值,下次可换 | `分厂 = 金工` |
| **有界可调 bounded** | 一个量,有合理范围/集合 | `提前天数 ≤ 7` |

AI **提议这条谱 + 给理由**;人用对话拨("分厂固定金工" → 锁;"日期以后要变" → 开;"最多提前10天" → 改上界)。参数谱可随时被对话查询与修改。

### 3.3 触发方式(时间维度)
- **现在跑一次**(ad-hoc,默认);
- **定时**(每隔一段);
- **事件触发**(后期)。
从对话设:"以后每周一早上自动跑" → 带上定时。(触发是致用录的一个字段,不是另一个概念——见 §6 决定 2。)

## 4. 生命周期(全对话 + 确认)

```
对话 grounded
  → agent 提议结晶("这段能复用,存成致用录?给你看致用卡")
  → 人对话确认 / 调参数谱 / 调触发
  → 存入致用录(库)
  → 触发:对话唤起("跑瓶颈救火,提前5天") / "+" 菜单选 / 库里 Run
  → 跑(危险步暂停等确认;有界值守界;结果内联 artifact 渲染)+ 记录执行历史
  → 要改 → 继续对话改
```

**结晶前的验证(补研究界的质量闭环)**:存之前对归纳出的致用录做一次**影子 / dry-run 复现**,比对原轨迹结果,不一致就提示/精炼。

## 5. 治理与诚实(护栏,非可选)

AI 猜错弹性有代价(不该动的设成可调 → 悄悄干错;该动的锁死 → 不好用)。故必须:
- AI 提议参数谱时**给理由 + 标 inferred**;
- 人可**对话纠正**任意一项;
- **危险 / 落库步骤跑时要人确认**(信任分级:安全步自动、危险步确认);
- **有界值跑时不越界**;
- 每条致用录有**致用卡**(§6)作透明层,跑前看得懂它会干啥。

## 6. UI / 信息架构(含两个已决定的待定)

**不新增平级 tab。分层复用现有面。**

**决定 1 —— 触发重心 = 对话唤起为主("agent 的手艺"),库作管理兜底。**
差异化在此:n8n/Zapier/Lindy 都是"自动化清单库"红海;"跟 agent 说一句、它就把学会的事干了"才是 Veylin 的 AI-native 楔子。
风险 = 想不起来 → 对策:**agent 主动提示** + **"+" 菜单可浏览选**(都在对话内),致用录库作可浏览兜底 + 排期/团队管理。
**三条唤起路径(全在对话内)**:①说("跑X")②agent 主动提示 ③composer 的 **"+" 菜单**里选一条致用录(复用现有 `composer-plus-menu`)。

**决定 2 —— 用户可见层合并成一个致用录库;后端前期不重构。**
现 Veylin 有 **"自动化"(Automate,单步 cron/事件)** 与 **Workflow(多步 DAG)** 两概念。用户视角它们是同一类:"一个可复用能力 + 一个触发"。故 **UI 上合并成一个「致用录(Playbooks)」库**(把"自动化"并入,单步/多步、手动/定时只是内部差异 + 触发字段)。**Phase 1 只做呈现层合并,不重构后端** Automate/Workflow 分家——结晶出的致用录呈现在统一库即可,内部该走 workflow 引擎走 workflow。

| 动作 | 落点 |
|---|---|
| 创建 | **对话里**("存成致用录") |
| 主触发 | **对话里**(说 / agent 提示 / "+" 菜单)+ 库里 Run 兜底 |
| 浏览 / 管理 / 排期 / 历史 | **左侧「致用录」**(升格并吸收原"自动化"):列出所有致用录,每条:名字、参数谱一览、触发、上次运行、Run |
| 看得懂它做啥 | **致用卡**(纯文字,非 DAG),存时 + 库里可看 |
| 编辑 | **对话改**(前期不做可视化 DAG 编辑) |

**致用卡示例(纯文字透明层,抄 ClawHub "Skill Card"):**
```
瓶颈救火 · 致用录 (Playbook)
步骤:拉负荷 → 找瓶颈 → 提前 N 天 → 影子验证 → 提交[需确认]
可调:分厂 · 提前天数(≤7)   固定:reschedule, 提交
触发:手动 / 现在
来源:2026-07-07 与 agent 的对话
```

**明确推迟**:右侧 Workflow 面板的**可视化 DAG 编辑**。理由:①手画节点是老范式;②对话改更 AI-native;③前期省一大块。DAG 编辑留作后期给 power user / 手搓致用录。

## 7. 架构与复用(别造轮子)

### 7.1 执行底座:直接复用 mastra Workflow 原语(Veylin 已在其上)
| 我们需要 | mastra 现成 |
|---|---|
| 程序化建流程(轨迹→致用录) | `createWorkflow()` + `.then()` + `.commit()` |
| 参数谱 | workflow `inputSchema`(Zod/JSON Schema) |
| 危险步人确认 | suspend + human-approval |
| 影子验证 / 复现 | time-travel 回任一步 replay |
| 执行历史 / 状态 | 自动持久化 workflow state |

### 7.2 模型抄成熟产品
- **OpenAI Codex Record & Replay → Skill**:演示→录→蒸馏(=我们的"对话→结晶")。
- **ClawHub Skill Card**:致用卡 = 做什么 + 来源 + 安全(=我们的透明层)。
- **WRITER / Salesforce Playbooks**:多步、可触发、团队共享的编排——就是 Playbook 定位本身。

### 7.3 我们只写这薄薄一层
1. **蒸馏器**:对话 tool-call 轨迹 → mastra `createWorkflow()` spec + 参数谱提议(一个 agent + schema 输出)。
2. **致用卡**:spec → 纯文字卡(渲染 + 存)。
3. **致用录库**:列表 + Run + 触发/排期 + 历史(升格并吸收现有"自动化"面)。
4. **对话动作**:"存为致用录" / "跑X" / "把X改成可调" 的 agent 工具与意图识别;"+" 菜单接致用录列表。

### 7.4 不拿
n8n / Flowise / Dify —— 可视化 DAG 优先,正是要推迟的老范式,不 fork。

## 8. 范围

**Phase 1(最小闭环,轻)**
- 对话里"存为致用录" → 蒸馏成 mastra workflow(**参数谱可先最小:仅锁定/可调两档,或先全锁定的高保真 replay**)→ 致用卡 → 存入致用录库 → "跑X"/"+"菜单/Run → 危险步确认 → 执行历史。
- **不做**:可视化 DAG 编辑、有界参数、定时/事件触发、跨模型编译、后端重构。

**Phase 2**
- AI 推理完整参数谱(含有界)+ 对话拨边界;存前影子验证;定时/事件触发。

**Phase 3+**
- 致用录随使用共演化(反馈回流);分享/分发(Plugins 式);可选可视化 DAG(power user)。

## 9. 待定 / 风险

- **决定 1、2 已定**(见 §6):触发重心=对话唤起为主;UI 合并成致用录库、后端前期不重构。
- **参数误判代价**:靠"AI 给理由 + 人可对话纠正 + 危险步确认 + 有界守界"兜底(§5)。
- **蒸馏质量**:一段轨迹是一个实例,泛化靠影子验证闭环;Phase 1 先只支持"高保真 replay"降风险。
- **命名落地**:中文「致用录」/ 英文 `Playbook`;侧栏"自动化"→"致用录"(待与 dezhao 上游 UI 术语对齐)。
