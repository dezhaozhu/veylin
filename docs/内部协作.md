# 内部协作说明(仅存在于内网仓库)

这份文档只在内网 GitLab 的这条线上,不会出现在外部仓库。

## 这条线是什么

内网 GitLab 的 `main` 是**内部协作主线**。它的第一个提交是一次完整快照(创世提交),之后就是一个普通仓库——**正常开分支、提 MR、合并**。

**它不会再被强推覆盖。** 之前的做法是每次更新就重新打包快照并强推,那会让所有人在上面的工作凭空消失;现在改成只追加。如果你发现 `git pull` 需要 `--force` 或提示历史不相关,**先别动,来问一声**——那说明有人误用了旧做法。

> 维护者:GitLab 的 `main` 分支保护(禁止强推)应当保持**开启**。它就是这条规矩的执行者。

## 同事怎么参与

```bash
git clone http://10.84.3.239:8081/gushirui/veylin.git
cd veylin && npm install
git checkout -b feat/你的特性
```

改完跑验证,再提 MR:

```bash
cd apps/server && VEYLIN_DATA_DIR=/tmp/vt-$$ npx tsx --test --test-concurrency=1 "src/**/*.test.ts"
cd ../web && npm test && npm run typecheck && npm run build
```

环境怎么起、怎么连排产后端,见 [compass-integration.md](compass-integration.md)。

## 维护者:两条血统怎么同步

这个项目在外部还有一条开发线。两条线**没有共同祖先**,所以只能靠搬运,不能 merge:

- **外部 → 内网**:`git cherry-pick` 成内网的普通提交
- **内网 → 外部**:同事在内网合并的改动,也要挑回外部线,否则外部会缺

搬运时如果碰到冲突,以**功能意图**为准重新落地,不要机械解冲突——两条线的文件可能已经各自演进。

**永远不要**:对内网 `main` 强推;把外部线直接推到内网 `main`。
